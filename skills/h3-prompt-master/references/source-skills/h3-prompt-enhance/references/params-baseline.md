# 参数基线建议值

`SKILL.md` 只管提示词，但提示词的**台词预算、段数、时长**必须和参数一起定。这份表给建议值，全部可配置。

---

## 1. 推荐组合配方（按用途选一套）

| 用途 | 段数 | 每段时长 | 画幅 | 台词 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 8G 卡竖屏口播长片（源工作流档位） | 10 | 10s | 736×1280 | 中文旁白，每段 30–55 字 | 已验证组合，总长约 100s |
| 短平快口播 | 5 | 5s | 736×1280 | 每段 20 字左右 | 总长约 25s |
| 横屏叙事/预告 | 3 | 5s | 1280×736 | 每段 20 字左右 | 官方 16:9 档，适合 storyboard 方言 |
| 高画质短片 | 3 | 10s | 1344×768 | 每段 40 字左右 | 官方 768p，显存需求最高 |

**段数与时长的选择原则**：主体/场景要变就分段；同一场景内只换动作就拉长单段。**不要把 12s 以上的内容硬塞进一段** —— 超过 12s 优先拆段，而不是扩写提示词。

---

## 2. 续接节点参数默认值

基于 `Herrgotts-H3-Infinite-Continuation-Suite` v1.4 的推荐基线（`README.md` 第 146–162 行）：

| 参数 | 建议值 | 为什么 |
| --- | --- | --- |
| `duration_mode` | `Net New Content` | 让每段"可见新增内容"贴合你写的时长 |
| `masked_context_frames` | `39` | 约 1.625s @24fps，显存与连贯的平衡点 |
| `audio_tail_carryover` | `Full Previous Tail` | **有台词必选**：让词尾/音素在视觉切点后仍能存活 |
| `audio_feather_ticks` | `0` | 语音场景保持硬保护，非零会削弱音素连续性 |
| `ref_image_size` | `match` | 参考图尺寸跟随目标 |
| Auto Handover `preset` | `Balanced` | 冻结/亮度安全的默认档 |
| Auto Handover `context_frames` | `"39"` | v1.4 固定为 39，不可调 |
| Safe Tail Bridge | `0` | v1.4 原生掩码 AV 下保持关闭 |
| Video crossfade | 4 帧 | 与官方基线一致 |
| Audio de-click crossfade | 15 ms | 与官方基线一致 |
| Boundary luminance matching | `Off` | legacy 回退项，仅在刻意 A/B 接缝时开 |

**这组值就是源工作流正在用的**（实测 widget 值见 `h3-prompt-spec.md` 第 6 节），所以按它写提示词不需要额外适配。

## 3. 时长 ↔ 帧数换算

H3 的合法总帧落在 **17k+5** 网格上（24fps）。

`Net New Content` 下：

| 请求时长 | 总帧 | 保护头 | 实际新增 | 新增时长 |
| --- | --- | --- | --- | --- |
| 5s | 158（官方实测） | 39 | 119 | ≈4.96s |
| 10s | 277（按同一规则推算，未实测） | 39 | 238 | ≈9.92s |

旧的 `Total Generation` 行为下，`5s` 仍是 124 总帧 = 85 新帧（≈3.54s）。**写台词按"实际新增时长"算，不要按请求时长算** —— 这是台词超时的常见原因。

---

## 4. 台词预算随段长缩放

`建议字符数 ≈ 实际新增时长(秒) × 4`（中文含标点，**不含 `[Chinese]` 语言标签**）。源十段实测 32–59 字符/10s，即 3.2–5.9 字符/秒，都在可念范围内。

| 段长 | 台词建议 | 硬上限 |
| --- | --- | --- |
| 5s | 18–22 字 | 25 字 |
| 10s | 30–45 字 | 60 字 |
| 15s | 50–60 字 | 70 字 |

超限的信号：不是"模型念不完"，而是**关键词被挤到段尾，撞上 39 帧边界**（见 `SKILL.md` 规则 6）。

## 5. 低显存（8G 档）相关

源工作流在 8G 卡上的做法，写提示词时可以放心用 10s / 736×1280，但**不要指望靠提示词规避显存问题**：

| 手段 | 节点 |
| --- | --- |
| int8 底模 | `minimax_h3_fl2va_pruned_int8_convrot.safetensors` |
| int8 文本编码器 | `qwen3vl_32b_minimax_h3_int8_convrot.safetensors` |
| 8 步 turbo LoRA | `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors` |
| 稀疏注意力 | `BlockSparseAttention` |
| 分块 FFN | `MiniMaxChunkFeedForward` |
| 注意力后端 | `ModelAttentionBackend` |
| 分辨率下探 | `736×1280`（短边 736 < 官方 768） |
| 精度切换 | `XHImagePrecision`（子图内 `bf16`，输出还原 `fp32`） |

**提示词侧的显存无关性**：提示词长度对显存影响可忽略，但对**时长**影响显著。要在 8G 上验证新风格，先跑单段 5s，再放量到 10 段。

## 6. 回填工作流的操作要点

改提示词只改 `Text Multiline` 节点的 `widgets_values[0]`：

```
Text Multiline(widgets_values[0]) → Set_提示词N → Get_提示词N → 子图 prompt
```

- 段号 → 节点 id：`1→545, 2→546, 3→547, 4→548, 5→553, 6→549, 7→550, 8→551, 9→552, 10→555`。
- **不要按节点 id 排序**，段序由 `Set_提示词N` 的 N 决定。
- 只替换 `widgets_values[0]` 字符串；不要动 `title`、`inputs`、`outputs`、`links`。
- **改前备份**工作流 JSON（源目录已有 `backup/` 惯例可循）。
- 提示词里的换行必须保留：三段之间是空行分隔（`\n\n`），整段文本是一个字符串。
- 因为每段提示词**自包含**（规则 1），可以只替换其中一段而不动其余九段。
